# PHM 오토인코더 기반 이상탐지 시스템 — 요구사항 정의서

- 문서 버전: v0.1
- 작성일: 2026-07-14
- 상태: 초안 (Draft)

---

## 1. 개요

### 1.1 배경
PHM(Prognostics and Health Management, 예지정비) 분야의 데이터는 **정상 데이터는 풍부하지만 비정상(고장/이상) 데이터는 극히 희소한 클래스 불균형** 특성을 가진다. 이 때문에 이상 데이터를 직접 라벨로 학습하는 지도학습 접근은 데이터 확보·재현·일반화 측면에서 제약이 크다.

### 1.2 목적
역발상으로 **정상 데이터만 오토인코더(Autoencoder)에 집중 학습**시켜 "정상 패턴의 복원 함수"를 만든다. 학습 분포에서 벗어난 비정상 데이터가 입력되면 입력과 출력(복원 결과)의 차이(**재구성 오차, reconstruction error**)가 커지므로, 이 오차를 임계값과 비교해 이상 여부를 탐지한다.

### 1.3 최종 산출물
사용자가 **CSV 파일을 업로드하면 웹 화면에서 이상 여부를 테스트**할 수 있는 형태로 구성한다.

### 1.4 접근 방식 요약
```
정상 데이터 → 전처리(정규화) → AE 학습(정상 패턴 복원 학습)
                                     │
정상 데이터의 재구성 오차 분포 → 임계값(threshold) 산출
                                     │
신규 CSV → 동일 전처리 → AE 복원 → 재구성 오차 계산 → 임계값 비교 → 정상/이상 판정
```

## 2. 시스템 목표 및 범위

### 2.1 목표
- 정상 데이터만으로 학습 가능한 비지도(준지도) 이상탐지 모델 구축
- 재구성 오차 기반 이상 점수(anomaly score) 및 정상/이상 판정 제공
- CSV 업로드 기반 웹 테스트 인터페이스 제공
- 어느 피처(센서)가 이상에 기여했는지 설명 정보 제공

### 2.2 범위 (In Scope)
- 데이터 전처리 및 스키마 검증 파이프라인
- 오토인코더 학습/추론 파이프라인
- 임계값 산출 및 저장
- 모델·스케일러·임계값·스키마 아티팩트 관리
- 웹 기반 CSV 업로드/판정/시각화 UI
- 평가지표 산출(라벨이 일부라도 있을 경우)

### 2.3 범위 외 (Out of Scope, 초기 버전)
- 실시간 스트리밍 추론(초기에는 배치/파일 단위)
- 자동 재학습(concept drift 대응) — 설계만 반영, 구현은 후속
- 사용자 인증/권한 관리
- 대규모 분산 학습/서빙

## 4. 추가 고려사항 (설계 반영 필수)

일반적인 AE 이상탐지 튜토리얼과 달리, 실사용 시스템이 되기 위해 아래 요소를 요구사항에 명시적으로 반영한다.

| # | 고려사항 | 반영 방침 |
|---|----------|-----------|
| 1 | **정상 데이터 오염** | 학습 "정상" 데이터에 이상치가 섞이면 모델이 이상을 정상으로 학습. 학습 전 통계/이상치 필터로 순수성 점검. |
| 2 | **정규화 파라미터 누수 방지** | 스케일러(mean/std, min/max)는 **정상 학습 데이터에서만** fit → 저장 → 추론 시 transform만 적용. |
| 3 | **임계값 결정 전략** | 정상 재구성 오차 분포의 백분위수(기본 99%) 또는 mean+kσ. 소수 이상 샘플이 있으면 검증셋으로 튜닝. |
| 4 | **시계열 vs 행단위** | PHM 데이터는 보통 시계열. 초기엔 행 단위(Dense AE) 지원, 시퀀스가 중요하면 윈도우 + LSTM/1D-CNN AE로 확장. |
| 5 | **AE 과용량** | 병목이 과도하면 이상치도 잘 복원 → 탐지 실패. 병목 차원 축소, L2/드롭아웃, Denoising AE 옵션. |
| 6 | **평가지표** | 불균형이므로 정확도 금지. Precision/Recall/F1, PR-AUC, ROC-AUC, 혼동행렬. |
| 7 | **설명가능성** | 피처별 재구성 오차를 제공해 이상 원인(어느 센서) 진단 지원. |
| 8 | **CSV 스키마 검증** | 학습 시 컬럼명/순서/타입을 스키마 아티팩트로 저장, 업로드 CSV와 대조·검증. |
| 9 | **아티팩트 세트 관리** | 모델 + 스케일러 + 임계값 + 스키마 + 메타데이터를 한 버전으로 저장(재현성). |
| 10 | **결측/상수/이상 컬럼 처리** | 결측 대치 정책, 분산 0 컬럼 제거 규칙 정의. |
| 11 | **Concept drift** | 정상 상태 변화 대비 재학습 트리거/모니터링 설계 반영(구현은 후속). |
| 12 | **재현성** | 랜덤 시드 고정, 의존성 버전 고정. |

## 5. 기능 요구사항 (Functional Requirements)

### FR-1 데이터 입력 및 검증
- FR-1.1 CSV 파일 업로드(웹) 및 로컬 경로 입력(학습 스크립트) 지원
- FR-1.2 업로드 CSV의 컬럼명/순서/타입을 저장된 스키마와 대조, 불일치 시 명확한 오류 메시지 반환
- FR-1.3 결측값/비수치 값 검출 및 정책(대치 또는 거부) 적용
- FR-1.4 (선택) 시간 컬럼 및 라벨 컬럼 인식 지원

### FR-2 전처리
- FR-2.1 수치형 피처 정규화(StandardScaler 기본). 스케일러는 학습 정상 데이터로만 fit
- FR-2.2 분산 0(상수) 컬럼 제거, 결측 대치 규칙 적용
- FR-2.3 (확장) 시계열 윈도잉(window size, stride) 옵션

### FR-3 모델 학습
- FR-3.1 정상 데이터만으로 AE 학습(입력=출력=정상 데이터)
- FR-3.2 학습/검증 분할, EarlyStopping, 손실(MSE) 모니터링
- FR-3.3 하이퍼파라미터(은닉층 크기, 병목 차원, epoch, batch, lr) 설정 가능
- FR-3.4 학습 완료 시 아티팩트(모델/스케일러/스키마/메타) 저장

### FR-4 임계값 산출
- FR-4.1 정상 데이터 재구성 오차 분포로부터 임계값 계산(기본: 99 백분위수)
- FR-4.2 임계값 산출 방식 및 값 저장, 근거 분포 시각화 저장

### FR-5 추론/탐지
- FR-5.1 신규 CSV → 전처리 → 복원 → 샘플별 재구성 오차 계산
- FR-5.2 오차 ≥ 임계값이면 이상(anomaly), 미만이면 정상 판정
- FR-5.3 샘플별 이상 점수, 판정 결과, 피처별 오차 기여도 출력
- FR-5.4 결과를 CSV로 다운로드 제공

### FR-6 웹 인터페이스
- FR-6.1 CSV 업로드 UI
- FR-6.2 판정 결과 표(샘플별 정상/이상, 오차, 점수) 표시
- FR-6.3 재구성 오차 시계열/분포 그래프 + 임계값 선 + 이상 하이라이트
- FR-6.4 피처별 기여도(상위 이상 원인 센서) 표시
- FR-6.5 결과 CSV 다운로드 버튼
- FR-6.6 임계값 조정 슬라이더(선택) — 판정 민감도 인터랙티브 확인

### FR-7 평가(라벨 제공 시)
- FR-7.1 라벨 컬럼이 있으면 Precision/Recall/F1/ROC-AUC/PR-AUC/혼동행렬 산출·표시

## 7. 데이터 요구사항

### 7.1 입력 CSV 형식(기본 가정)
- 각 행 = 하나의 관측(스냅샷) 또는 시계열 타임스텝
- 각 열 = 센서/피처 (수치형)
- 선택 컬럼: `timestamp`(시간), `label`(0=정상, 1=이상, 평가용)
- 헤더(컬럼명) 필수

### 7.2 데이터 분할
- 학습: 정상 데이터만
- 검증: 정상 데이터 일부(+가능하면 소수 이상)로 임계값 튜닝
- 테스트: 정상+이상 혼합으로 최종 평가

---

## 8. 모델 설계 고려사항
- 기본 아키텍처: 대칭형 Dense Autoencoder (Encoder–Bottleneck–Decoder)
- 손실: MSE(재구성 오차)
- 활성화: ReLU(은닉), 출력층 선형/적절한 활성
- 정규화: 병목 차원 축소, L2/Dropout, 옵션으로 Denoising AE
- 확장: 시계열 중요 시 LSTM-AE 또는 1D-CNN-AE
- 재구성 오차: 샘플별 MSE(피처별 오차도 함께 산출)

## 9. 시스템 아키텍처(안)
```
┌────────────┐   업로드   ┌──────────────┐   추론요청   ┌────────────────┐
│  웹 프론트  │ ────────► │   백엔드 API  │ ──────────► │  추론 파이프라인 │
│ (업로드/시각화)│ ◄──────── │ (검증/서빙)   │ ◄────────── │ 전처리→AE→오차   │
└────────────┘   결과JSON  └──────────────┘   결과      └────────────────┘
                                   │ 로드
                                   ▼
                      아티팩트(모델/스케일러/임계값/스키마)
```
- 학습(오프라인): `train` 스크립트 → 아티팩트 생성
- 서빙(온라인): 웹앱이 아티팩트 로드 → CSV 추론

## 14. 열린 결정사항 (확인 필요)
> 아래는 기본값을 가정해 진행하되, 사용자가 지정하면 반영한다.

1. **데이터 형태**: 행 단위(tabular) 기본 가정. 시계열 시퀀스가 핵심이면 윈도우+LSTM/CNN-AE로 확장.
2. **웹 스택**: 빠른 테스트 목적이면 **Streamlit** 권장(단일 앱). 향후 서비스/확장 고려 시 **FastAPI + 프론트**.
3. **DL 프레임워크**: TensorFlow/Keras 기본. PyTorch 선호 시 변경.
4. **라벨 유무**: 평가 자동화를 위해 소수라도 이상 라벨 데이터 확보 가능 여부.
5. **샘플 데이터 제공 여부**: 실제 센서 CSV 스키마 공유 시 스키마 검증을 실데이터에 맞춤.
